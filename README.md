# DAA Assignment 3 — Graphs

Реализованы представление графа списками смежности, чтение из файла и DSU.

## Требования и запуск

JDK 25 (как настроено в pom.xml) и Maven 3.9+.
Команды выполняются из корня проекта:

```shell
mvn test
mvn package
java -cp target/classes org.example.Main data/connected.txt
```

В IntelliJ IDEA можно открыть Maven-проект, выбрать JDK 25 и запустить
`Main`. Без аргументов он читает `data/connected.txt`.

## Формат данных

```text
n m directed|undirected
u v w
```

После заголовка идут ровно `m` строк с рёбрами. Вершины: `0 .. n-1`,
веса: `int`, включая отрицательные. Пустые строки в конце допустимы.
Некорректные данные вызывают `IOException` с описанием причины.

Примеры: `connected.txt` — связный неориентированный граф,
`disconnected.txt` — несвязный граф с изолированной вершиной,
`cyclic.txt` — ориентированный граф с циклом.

## Код

- `Graph`: единый тип для ориентированных и неориентированных графов.
- `Edge`: неизменяемое ребро `(from, to, weight)`.
- `GraphReader`: загрузка и проверка входного файла.
- `Main`: вывод прочитанного графа.
- `GraphTest`: JUnit 5 тесты графа, примеров и ошибочных файлов.
- `DSU`: система непересекающихся множеств со сжатием путей и объединением по размеру.
- `DSUTest`: проверка DSU, включая сравнение с простой эталонной реализацией.

`edges()` содержит каждое добавленное ребро один раз. В списках смежности
неориентированное ребро хранится в обоих направлениях; петля имеет две записи.
Параллельные рёбра сохраняются. Возвращаемые списки доступны только для чтения.

`new DSU(n)` создаёт `n` отдельных множеств. `makeSet(n)` повторно инициализирует
структуру и обнуляет счётчики. `find(x)` возвращает представителя множества,
`union(x, y)` возвращает `true`, если множества были объединены,
а `components()` — текущее число множеств.

`findCalls()` считает вызовы `find`, включая вызовы внутри `union`.
`successfulUnions()` считает только успешные объединения.
`dsuOps()` возвращает сумму этих двух счётчиков. Некорректные аргументы
вызывают `IllegalArgumentException` без изменения структуры и счётчиков.

MST, SCC, топологическая сортировка, кратчайшие пути и benchmark
предназначены для следующих этапов.
